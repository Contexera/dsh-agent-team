## Findings

### F1 — Deferred notification path swallows invariant divergences (contract violation)
- **Severity:** medium
- **Location:** `packages/agent-team/src/index.ts:2737-2747` (deferred branch) vs `:2758-2763` (synchronous branch); doc contract at `:2729-2733`.
- **Evidence:** The synchronous `afterCommit` re-raises `AgentTeamInvariantError` (`if (error instanceof AgentTeamInvariantError) throw error`, :2761). The new deferred branch catches **every** error and logs it: `catch (error) { this.ctx.logger.warn('agent-team: post-commit ${label} failed: …') }` (:2742-2743). `deliverInboxNotice` deliberately re-raises `AgentTeamInvariantError` (:2932), and it is reached through `notifyMember` from the deferred effect.
- **Impact:** For any commit affecting ≥8 Members (`NOTIFICATION_QUEUE_THRESHOLD`, :194), an integrity divergence inside the notification effect is folded into an ordinary warn instead of staying loud. This contradicts the method's own contract comment ("An invariant divergence is the exception: it is re-raised on the caller's frame so a failed integrity check stays loud") and weakens ticket 02 criterion 2/3 ("wake、recovery、generation swap、通知派生失败和 steer 失败的行为保持现有隔离语义").
- **Basis:** ticket 02 unchecked item "wake、recovery、generation swap、通知派生失败和 steer 失败的行为保持现有隔离语义"; spec "失败隔离逐项一致".
- **Fix:** In the deferred branch, do not fold `AgentTeamInvariantError` into the generic warn — surface it distinctly (e.g. `this.ctx.logger.error` naming the invariant, or a dedicated handler). Async propagation cannot reach the caller frame, so record the divergence at a level that is not silent.

### F2 — Ticket 01's clean-commit criterion genuinely unmet, and the matrix manifest cannot prove it
- **Severity:** medium
- **Location:** `scripts/team-performance/run-team-performance-matrix.mjs:25-28`; `scripts/team-performance/team-performance-baseline.ts:908-911`.
- **Evidence:** All 182 run manifests under `artifacts/team-perf/runs/*/manifest.json` report `dirty: true`; the baseline records `commits` + `dirty` + `status`, but the **matrix** manifest records only `runId, startedAt, samples, warmups, cases, node` — no commit, no dirty flag. So the minimal-matrix artifact carries no clean-tree evidence at all.
- **Impact:** Ticket 01's one open item ("在 clean commit 上跑通最小矩阵，并保留复跑命令和限制") is not satisfied, and cannot be satisfied by the matrix runner as written because it never records the tree state.
- **Basis:** ticket 01 `- [ ] 在 clean commit 上跑通最小矩阵，并保留复跑命令和限制；当前验证工作树包含其他未提交修改`.

### F3 — Ticket 02's "逐项一致" criterion is not verified by any probe

- **Location:** `scripts/team-performance/team-performance-semantics.ts:152-172`; `packages/agent-team/tests/inbox-delivery.spec.ts`.

## Findings

### 1. MEDIUM — the `running` early return suppresses the retry for `undelivered` threads
`packages/agent-team/src/index.ts:2837-2841` (`notifyMember`, not `notifyMemberAtWake` as the brief said).

The guard is `cause.kind === 'running' &amp;&amp; delivery?.covered !== undefined &amp;&amp; delivery.covered !== ''`. `covered` is `plan.delivered` from `coverInboxFacts`/`beginInboxDelivery` (`index.ts:3305-3317`), and by construction `delivered` **deliberately excludes threads the notice could not render** (`inbox-delivery.ts:70-78`: `if (now.length &gt; 0 &amp;&amp; !undelivered.has(threadRef)) delivered.push(...)`).

Concrete trace: a single commit mentions member M in 9 Threads. `notificationText` caps rendered scopes at 8 (`index.ts:3169-3177`) and returns `undelivered = [T9]` (`index.ts:3211`). `beginInboxDelivery` records `covered = signature(T1..T8)` — **non-empty** — plus `undelivered: [T9]`. Under the old code, when M's own turn starts the `agent/status → 'running'` edge runs `deliverInboxNotice`, `inboxDeliveryPlan` sees `plan.signature` (includes T9) ≠ `covered` → `trigger === 'immediate'` → T9 is re-attempted. With the early return, the `running` edge returns before `deliverInboxNotice`: `covered !== ''` is true, so T9's facts wait for the next commit/activation touching M.

Impact: M's direct mention in T9 is durably unread but is not re-attempted on the member's own next run edge. No data loss (the facts rederive on the next commit), but the retry surface documented in `inbox-delivery.ts` ("an unchanged rederivation still sees them as owed and re-attempts instead of standing down") is narrowed to commit/activation causes only. Consistent with the coordinator's finding that removing the block changes no test outcome — no test covers the `undelivered` retry.
Smallest fix: add `&amp;&amp; delivery.undelivered.length === 0` to the guard (or replace the block with `plan.trigger === undefined`, which is exactly the dedup below and makes the new block redundant).

### 2. LOW — "coverage non-empty" is a weaker test than the dedup it pre-empts
Same block. The existing dedup (`index.ts:2899`) compares the *full* signature against `covered`; the new guard short-circuits before that comparison exists. Any future state where `covered` is stale-but-non-empty (a commit whose notice was skipped — e.g. `notifyMember` returning at the `member.state !== 'enabled'` check at 2830-2833 — while new facts accumulated) now skips a read that the old code would have turned into a delivery. I traced every such path I could find (`state !== enabled`, transition in flight, deferred effect skipped at shutdown, `dropInboxCoverage` on failure) and each is followed by an activation/transition/commit cause that re-delivers, which is why I rate this LOW rather than a live bug.

### 3. LOW — the read set is instance state that assumes a synchronous read
`packages/agent-team/src/ledger.ts` (`notificationReadSet` field, `withNotificationReadSet`, `unreadFor`, `mainUnreadForNotification`). The cache is only sound because no `await` exists between set and `finally` restore, and ledger mutation happens only inside enqueued operation bodies (`enqueue`/`operationTail`, `ledger.ts:6619`). Correct today; a future `await` inside any of these reads silently turns the cache into cross-task staleness. Informational in nature, worth a one-line constraint comment.

### 4. LOW — benchmark counter is mislabelled
`scripts/team-performance/team-performance-baseline.ts:649-651`: the wrapper increments `notificationTextMissingPlan` when `args[3] === undefined`, but in the new signature `(agent, notifications, readerId, main, deliveryPlan, prefix)` index 3 is `main`, not the delivery plan. ### 5. LOW — fixture assertions that omit the location

- **A (parameter order) — rejected.** Exactly two call sites in `src`: `index.ts:1326` `(handle.agent, notifications, member.memberId, mainNotifications, undefined, text)` and `index.ts:2915` `(…, plan)`.
