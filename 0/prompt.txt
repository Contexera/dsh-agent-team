2. Key Technical Concepts:

   - Cordis/DeepSeek Harness 外部插件 `dsh-agent-team`，唯一 Team authority 是 `packages/agent-team`。
   - append-only operation ledger 是持久事实来源，投影、Remote、工具、Client 都不是平行 authority。
   - 重放会重新计算每条 operation 的 inbox delta，并用 `isDeepStrictEqual` 校验。因此改变旧 operation 的 inbox 推导会破坏真实账本回放。
   - `acceptedClaimRefs` 是已有判别字段先例：新记录显式保存新语义所需信息，旧记录无字段时走旧规则。
   - A 新增 `refollowedMembers`：
     - 新 reopen 必须携带，哪怕为空数组。
     - 旧 reopen 无此字段，继续 marker-only、不恢复 follow。
     - 不提升 rules version。
   - `Thread Attention` 控制普通 Thread 更新；activity/reminder marker 独立承担直接通知。
   - close 清空 Thread Attention 和 reminder/activity/direct markers；accept 不清 Attention。
   - reopen 恢复 accountable follow 时必须排除 actor 自身，并检查当前是否已经 following，避免重复添加。
   - `planInboxDelivery` 的提醒输入来自 `notificationFacts` → `memberInbox` → `remindersFor`。因此在 `remindersFor` 源头过滤，可同时覆盖 Inbox 显示和 Agent 唤醒，不需要另改 `inbox-delivery.ts`。
   - `reviewReminderRecipient` 统一待验收接收者规则：Human accountable、accountable 不再是 owner、accountable 曾持有 Claim 时由 Human 验收，否则由 accountable 验收。
   - 提醒过滤只判断持久事实可确认的当前有效性，不重新要求当前仍满足 Agent idle 30 分钟，避免 Host 重启丢失运行时 idle 观测后误删有效提醒。
   - 暂停成员不是失效条件：spec 明确 suspended 时保留 owner/accountable，提醒留在 Inbox，恢复后投递。曾加入 enabled 过滤，已撤回。
   - 持久 marker 不过滤删除；仍在 Task Thread read、accept、close、生命周期清理时按原规则消费。
