2. Key Technical Concepts:

- **Main stream Attention** (from the just-shipped work): a new `(memberId, projectRef)` row replacing identity-derived Main stream unread. `standing.owner` → `standing.following`.
- **Replay validation**: `AgentTeamLedger` validates every stored operation against a re-derived expectation on load. Any divergence throws, so a ledger written by an older build fails to open when a newer build changes what a delta must contain.
- **In-memory legacy repair**: the established pattern in this codebase (`repairLegacyProjectCleanup`, plus precedent commit `2980d54`). Applied inside `sortedRecords()` — the single replay entry point shared by `replay()` and `validate()` — so it never rewrites stored bytes, and it guards on an exact deep-equal of the legacy shape so a forgery is not silently accepted.
- **`inboxDelta` positional parameters** (12 params): `set, removed, addedMarkers, removedMarkers, addedActivityMarkers, removedActivityMarkers, addedMainMarkers, removedMainMarkers, addedReminderMarkers, removedReminderMarkers, setMainAttention, removedMainAttention`. mainAttention is positions 11/12 — a frequent source of silent bugs.
- **The lost watermark problem**: pre-Attention Agent Main stream reads stored their watermark in a `mainWatermarks` projection map that commit `51f58d8` deleted. Without repair, the watermark is unrecoverable from the ledger and the reader would see its entire history as unread. The repair must re-mint it from the read's own `readThroughSequence`.
- **Storage layout**: `~/.dsh/storages/agent_team.sqlite`, table `u_agent_team_operations (key TEXT PRIMARY KEY, value TEXT NOT NULL) STRICT`, 25356 rows. Opened in probes via `SqliteStorageBackend` from `packages/agent-team/src/vendor/storage-sqlite/index.ts`.
- **Build artifact staleness**: the `team-member` preset resolves `@contexera/dsh-agent-team/tools` from `node_modules` → `lib/`, so source changes to the tool surface require `npm run build` before integration tests pass.
- **Ledger instance isolation**: each `AgentTeamLedger` instance projects its own writes; a second instance opened on the same table does not see the first instance's in-memory projection.

  - **Change 2** — added `repairLegacyMainAttentionGrant` (with doc comment):
    ```ts
    /**
     * An owner grant written before Main stream Attention existed carries the
     * era's inbox: a Main marker alone, with no `mainAttention` row. That grant
     * still started its Member's default attention, so the missing row is
     * re-minted from the grant's own sequence and the record is repaired in
     * memory. Any other shape — a row already present, or a delta that differs
     * from the era's in some other way — is left alone, so it still fails
     * validation and a forgery is not silently accepted.
     */
    private repairLegacyMainAttentionGrant(operation: AgentTeamOperation, projection: Projection): AgentTeamOperation {
      if (operation.kind !== 'team/project-owner-added') return operation
      const { inbox, memberId, projectRef } = operation.data
      if (inbox.mainAttention !== undefined) return operation
      const granted = [this.startMainAttention(memberId, projectRef, operation.sequence)]
      // The era's delta: the owner-added Main marker and nothing else. A delta
      // that differs in any other way is a shape this build never wrote, so it
      // is left alone and still fails validation.
      const legacy = this.inboxDelta([], [], [], [], [], [], inbox.mainMarkers?.added ?? [])
      if (!isDeepStrictEqual(inbox, legacy)) return operation
      return { ...operation, data: { ...operation.data, inbox: this.inboxDelta([], [], [], [], [], [], inbox.mainMarkers?.added ?? [], [], [], [], granted) } }
    }
    ```
  - **Change 3** — added `repairLegacyMainStreamRead` (with doc comment):
    ```ts
    /**
     * An Agent's Main stream read written before Main stream Attention existed
     * carried only the markers it consumed: its watermark lived in a projection
     * field that no longer exists, so replay alone would lose every byte of read
     * progress and hand the reader its whole history as unread. The row is
     * re-minted from the read's own `readThroughSequence`, so the era's progress
     * survives. Only the era's shape is repaired — a receipt that differs in any
     * other way is a shape this build never wrote and still fails validation.
     */
    private repairLegacyMainStreamRead(operation: AgentTeamOperation, projection: Projection): AgentTeamOperation {
      if (operation.kind !== 'team/main-stream-read') return operation
      const { inbox, memberId, projectRef, readThroughSequence } = operation.data
      if (memberId === AGENT_TEAM_HUMAN_MEMBER_ID || inbox.mainAttention !== undefined) return operation
      const attention = this.mainAttentionForFrom(projection, memberId, projectRef)
      if (attention === undefined) return operation
      // The era's receipt: the markers it consumed and nothing else.
      if (!isDeepStrictEqual(inbox, this.inboxDelta([], [], [], [], [], [], [], inbox.mainMarkers?.removed ?? []))) return operation
      const advanced = Object.freeze({ ...attention, readThroughSequence: Math.max(attention.readThroughSequence, readThroughSequence) })
      return { ...operation, data: { ...operation.data,
        inbox: this.inboxDelta([], [], [], [], [], [], [], inbox.mainMarkers?.removed ?? [], [], [], [advanced]) } }
    }
    ```

    function stripMainAttention(delta: AgentTeamInboxDelta): AgentTeamInboxDelta {

    async function rewrite(team: Seeded, kind: string, rewriteInbox: (delta: AgentTeamInboxDelta) => AgentTeamInboxDelta): Promise<void> {
      const stored = [...team.table.entries()].map(([, operation]) => operation)
        .filter((operation): operation is Extract<AgentTeamOperation, { readonly data: { readonly inbox: AgentTeamInboxDelta } }> => operation.kind === kind)

        await team.table.put(operation.operationId, { ...operation, data } as typeof operation)

4. Errors and fixes:

- **The reported bug: `invalid Project owner inbox projection` on dev-profile startup.** Root cause: 11 `team/project-owner-added` records (sequences 24535…25235, written 2026-10-24) predate the `mainAttention` field in the grant delta, so the new replay expectation diverges. Fixed with the in-memory repair described above, following the existing `repairLegacyProjectCleanup` precedent rather than relaxing validation permanently.

- **Second failure after the first fix: `invalid Main stream read receipt`.** 56 Agent `main-stream-read` records also lack the row, and their watermarks lived in a projection map that no longer exists. Fixed by `repairLegacyMainStreamRead` re-minting the row from `readThroughSequence`.

- **My own parameter-position bug.** My first repair passed `([], [], [], [], [], [], mainMarkers, [], [], granted)`, so `granted` landed in position 10 (`removedReminderMarkers`). Diagnosed by instrumenting the validator: the "actual" side showed `reminderMarkers.removed` containing a `{startSequence, readThroughSequence}` row — exactly the shape of `startMainAttention` output. Fixed by passing one more empty array so `granted` reaches position 11.

- **Wrong guard comparison.** My first guard compared the stored delta against an empty-mainMarkers delta, but the real legacy delta carries a Main marker, so the guard never matched the real shape. Fixed to `this.inboxDelta([], [], [], [], [], [], inbox.mainMarkers?.added ?? [])`.

- **`json_extract` unreliability**: `json_extract(value,'$.data.inbox.reminderMarkers')` returned empty for a field that the parsed object actually had (and vice versa), because the value returned for a missing key is indistinguishable from an empty one. Switched to reading raw bytes with `substr` and `grep -o`, and to parsing the JSON in Python.

- **Probe script top-level await in CJS**: `node --import tsx/esm /tmp/probe-ledger.ts` failed with "Top-level await is currently not supported with the cjs output format". Fixed by renaming to `.mts`.

- **Probe copy couldn't resolve relative imports**: copying `ledger.ts` to `/tmp` broke `./time-format.ts`. Abandoned that approach and instrumented the real source in place, then removed the instrumentation.

- **Test: `mainAttentionStatus(...).following` was `undefined`.** The method returns `{ project, attention? }`, not a `following` flag. Switched to `mainStreamHistory(...).standing`.

- **Test: `expected 0 to be greater than 0`** after posting a third message. Two causes: (a) a Member never sees its own output as unread, so the Agent's own post can't create unread — switched to posting as Human; (b) `reopened` is a separate ledger instance with its own projection, so the post had to go through `reopened.postMainMessage`, not `team.ledger.postMainMessage`.

- **Typecheck TS2339** `Property 'inbox' does not exist on type ...` in the `rewrite` helper, because `operation.data` is a discriminated union. Fixed with a type predicate narrowing to `Extract<AgentTeamOperation, { readonly data: { readonly inbox: AgentTeamInboxDelta } }>`.
