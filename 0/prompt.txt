## 2. Key Technical Concepts

### 2.1 必须保持的三状态

区分：
1. 当前上下文完整提供了事实。
2. 显式 `team_thread read` 确认已读。
3. Host 已提交操作。

完整通知、read/history/message 结果、完整拒绝可以满足当前上下文条件，但：
- 通知／查询／回复成功不推进已读水位。
- 不消费未读 marker。
- 只有显式 read 确认。
- 每次写仍检查新事实、权限、Thread revision、Task 状态及验收资格。
- Main 不新增 Thread token。
- 当前 board/card 状态不证明历史 Activity 或对应 Thread 已读。

### 2.2 架构

- Team 是外部 opt-in Cordis bundle。
- `packages/agent-team` 唯一 Team authority。
- append-only ledger 是持久事实来源。
- `packages/tool-agent-team` 七个模型工具只通过隔离 `team-member` preset。
- Human 只有 Web Client 控制面。
- 不改相邻 Harness、agent loop、默认行为。
- 不新增第二套持久已读状态、通用上下文框架、通知数据库或兼容 fallback。

七工具：
`team_view`、`team_inbox`、`team_attention`、`team_thread`、`team_message`、`team_dm`、`team_task`。

### 2.3 当前 Session 完整事实判断

`packages/agent-team/src/surface-visibility.ts`

- SHA-256 绑定生产者实际完整输出文本。
- Message 绑定 Thread 或 Main Project、messageRef、bodyDigest；分段还带 start/end/total。
- Activity 绑定 immutable event 的身份及 factDigest。
- 只从当前 `session.surface.nodes` 派生的实际文本判断。
- Team notice 要正确 producer 和 `form:'notice'`。
- tool result 沿 `sourceEventSeqs` 找到同 callId 的真实 Team tool call。
- 通过 `deriveEventMessage(event)` 校验实际文本 digest。
- 文本裁掉但 metadata 保留，不算完整。
- 没有 substring、模型复述或“我看过”备用判断。
- identity-only／省略结果不能重新绑定被省略全文。
- queued notice 尚未进入 surface，不算可见。

已实现读取：
- read/message 总输出上限 32768 UTF-16 code units。
- 重复同请求从当前 surface 最早缺段继续，无 offset 参数。
- 一批过长先减条数，单 Message 仍过长才分段。
- read 完整覆盖才确认，不能越过未完整旧 Message。
- message 始终不确认。
- Activity 不分段，超过固定输出上限明确不确认并交 Human。
- history 仍 count-only 分页，未承诺总字符预算。
- `[attachment]` 路径只是定位，Message 完整不等于附件已读。

### 2.5 07 规则分工与保持行为

- persona：跨工具规则。
- tool description：选择工具和基本调用必需的契约。
- parameter description：格式、动作适用范围。
- result：本次状态和可执行恢复。
- core skill：详细方法和少见情况。
- 不能为了去重让基本调用必须先读教程。
- 不为所有 catch 增加“结果不确定”。
- 已提交但通知失败不能改判未提交或诱导重复写。
- DM 已记录未送达已有真实类型化路径及禁止盲重发说明，保留。

当前地址行为：
- Thread 和 Main `projectRef` 互斥。
- `read/history/attention` 同时给 `threadRef` 和 `taskRef` 可以，只要属于同一个 Thread。
- `message` 对 Thread 必须有 `threadRef`；单给 `taskRef` 拒绝。
- **既有 `message` 同时给 `threadRef + taskRef` 时，额外 taskRef 被忽略。**
- Main `message` 用 projectRef。
- 07 只准确描述，不新增拒绝额外 taskRef 的 guard。
- 自己持有 active Claim 才阻止 unfollow；其他人的 Claim 不阻止自己 unfollow。
- DM 文本中的 `@mention` 不额外投递，尤其不能借 DM 通知 Human。
- v1 `undeliveredMentions` 仅从模型出口移除，Host 历史 receipt/replay 保留。
