2.1 项目与架构

- dsh-agent-team 是外部安装、显式启用的 Cordis bundle，不修改 DeepSeek Harness 的 agent loop 或 shipped defaults。
- packages/agent-team 是唯一 Team authority。
- append-only operation ledger 是 Team durable facts 的来源。
- packages/tool-agent-team 只提供七个模型工具，位于显式 team-member preset：
  team_view、team_inbox、team_attention、team_thread、team_message、team_dm、team_task。
- Human Team 控制面仍是 Web Client。
- 自然语言输出不成为第二份状态来源；Client 不解析 Agent 文本恢复状态。
- typed Remote 声明生成 Typert 文件，禁止手改生成物。
- 当前相邻 Harness package 版本 0.2.1-rc.2，Team peer 范围 >=0.2.1-rc.2 <0.2.2。只核对了源码/声明，没有做运行时兼容认证。

2.3 三个必须区分的状态

1) 当前上下文完整提供了事实：
   来源、对象明确，必要内容在当前模型上下文中完整可用。
   不等于模型理解正确，也不等于持久已读。

2) 显式确认已读：
   通过 read，由 Host 修改既有阅读状态。
   不等于事项完成，不改变 Attention。

3) 操作已提交：
   Host 按当前权限、状态和并发条件提交。
   不等于通知送达，不顺带清除未读。

通知、回复、history、message 查询、自动背景补充都不主动确认已读。
历史已读不会因压缩撤销，但背景可能因压缩缺失，需要补充。

2.6 Q5 / Q12：写入阅读条件统一

- 不要求一定调用过 read；看当前上下文是否完整提供所需事实。
- 可以来自：
  完整通知、read/history/message、完整拒绝变化、字段齐全的 Task/Claim 事件。
- 不可以来自：
  数量、标题、摘要、截断正文、模型复述、“我看过了”。
- 看板当前状态只证明状态，不代表相关事件和讨论已提供。
- 必须对应具体事实、来源、实际可见内容。
- 不保留正文子串匹配兜底；“ok”出现在另一个 Thread 不算。
- 拒绝结果完整补齐后允许重新考虑再写，不必再读一份相同正文。
- 不保证重试成功；提交仍检查新消息、revision、权限和 Task 状态。
- 阅读豁免不写 ledger 已读、不消费 marker。
- Thread、Main、Message、Activity 用同一完整性原则，但保留各自权限和凭据差异。
- Main 不因此增加 Thread revision token。

2.9 Q9：长内容

- 普通消息尽量完整；批次放不下先减少条数。
- 单条过长明确分段及续读。
- 不静默截断后算已读。
- 返回范围与确认范围来自同一次选择。
- 不能先确认全批再由 renderer 裁剪。
- read 连续续读完整后确认对应消息。
- message 续读仍为查询，后续 read 可以确认并省略已可见正文。
- 不能跨过未完整消息推进连续水位。
- 当前缺段、压缩或裁剪不误判完整。
- 每步应前进或给可用入口，不能反复同一开头。
- 工程核对额外注明：若单条本身超出模型可承载容量，明确实际限制，不假称完整、不预建通用大文件框架。

2.10 Q10：结果状态

- 已记录但未送达

成功结果给必要对象、变化、凭据，不重放正文。
无必要下一步不硬加。
拒绝只给当前实际可执行恢复，不机械建议原样重试。
