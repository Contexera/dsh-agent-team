## 2. Key Technical Concepts

### 2.1 架构与 authority

- Team 是 opt-in、可外部安装的 Cordis bundle。
- `packages/agent-team` 是唯一 Team authority。
- append-only operation ledger 是持久 Team 事实来源。
- tools、通知、Session 可见性不能维护第二份已读数据库。
- 七工具职责保持：
  `team_view`、`team_inbox`、`team_attention`、`team_thread`、`team_message`、`team_dm`、`team_task`。
- Human 唯一控制面是 Web Client。
- Team identity、private memory、Team tools/guidance 只属于隔离的 `team-member` preset。
- 普通 Session 和 fork 不得继承 Team 能力。
- 不修改相邻 Harness 源码、agent loop 或 shipped defaults。
- Typert、tsconfig path facades 是生成物。

### 2.2 已确认的三个不同状态

1. 当前上下文完整提供事实。
2. 显式 `read` 确认已读。
3. Host 操作提交。

具体约束：
- 完整事实可满足写前阅读条件，但不代表确认已读。
- 通知、拒绝、history/message 查询、自动背景和回复都不推进 watermark、不消费 marker。
- 获得 token 不保证下一次提交；仍检查新未读、revision、权限、Task 状态。
- Main 不新增 Thread revision token。
- 长消息未完整提供前不能确认；后面事实不能跨过未完整的一条推进连续水位。
- 返回内容选择和确认范围必须来自同一次选择。
- 不允许先确认整批，再在 renderer 截断正文。

export type ThreadMessageSurface = {
  readonly textDigest: string
  readonly messages: readonly {
    readonly threadRef: string
    readonly messageRef: string
    readonly bodyDigest: string
  }[]
}

export interface RenderedThreadMessage {
  readonly threadRef: string
  readonly messageRef: string
  readonly body: string
}

const digest = (text: string): string =>
  createHash('sha256').update(text).digest('hex')

export function threadMessageSurface(text: string, messages: readonly RenderedThreadMessage[]) {
  return {
    textDigest: digest(text),
    messages: messages.map(message => ({
      threadRef: message.threadRef,
      messageRef: message.messageRef,
      bodyDigest: digest(message.body),

03 Thread 当前实现：
```
async readThreadForAgent(
  agent: Agent,
  request: AgentTeamThreadReadRequest,
): Promise<AgentTeamThreadReadResult & {
  readonly visibleMessageRefs: readonly AgentTeamMessageRef[]
}> {
  const actor = this.memberCall(agent, request.workspaceId)
  const result = await this.requireLedger().readThread({ ...request, actor })
  const surface = visibleTeamSurface(agent)
  const receipt = result.committed ? result.value.receipt : undefined
  if (receipt !== undefined) this.emitCommitted(receipt)

  const snapshot = result.value
  const unread = snapshot.facts.filter(entry => entry.unread)
  const history = this.requireLedger().threadHistory(actor, {
    ...request,
    beforeSequence: unread[0]?.fact.sequence ?? snapshot.thread.revision + 1,
    limit: 4,
  })
  const anchor = {
    fact: {
      kind: 'message' as const,
      sequence: snapshot.anchor.sequence,
      message: snapshot.anchor,
      mentions: snapshot.anchorMentions,
      occurredAt: snapshot.anchor.occurredAt,
    },
    unread: false,
    direct: false,
  }
  const background = [
    anchor,
    ...history.facts.filter(fact => fact.kind === 'message')
      .map(fact => ({ fact, unread: false, direct: false })),
  ].filter((entry, index, entries) =>
    !unread.some(item => item.fact.sequence === entry.fact.sequence) &&
    entries.findIndex(item => item.fact.sequence === entry.fact.sequence) === index &&
    !isFactOnSurface(surface, entry, snapshot.thread.threadRef))

  const facts = [...background, ...unread]
    .sort((left, right) => left.fact.sequence - right.fact.sequence)
  const read = this.withReplyContexts({ ...snapshot, facts }, request.workspaceId)
  if (receipt !== undefined) this.afterAcceptanceRead(agent, actor.memberId, read)
  const visibleMessageRefs = unread.flatMap(entry =>
    entry.fact.kind === 'message' &&
    isFactOnSurface(surface, entry, read.thread.threadRef)
      ? [entry.fact.message.messageRef] : [])
  return { ...read, visibleMessageRefs }
}
```

重要：
- surface 派生在 await ledger read 后，避免排队期间旧 visibility。
- 不把 presentation 字段加到 shared durable readFact type。
- `withReplyContexts` 仍批量 resolve 父引用，避免逐消息重复。
- history 查询同步、不写 operation。
