5. Problem Solving:

   **Solved — Round 1 factual answer:** A Task Thread's creator *does* receive subsequent messages. `inboxDeltaForTaskResponsibility` (ledger.ts:4759) grants the anchor sender attention, so the creator is a follower of what it started. Delivery for an owner is threshold-batched (5 ordinary updates per Member×Thread), a mention is immediate and carries waiting ordinary updates, and an explicit unfollow stops ordinary updates entirely. Verified with 4 passing scratch tests.

   **Solved — Round 2/3 gap verification:** Both gaps are real and measured. But crucially, **follow/unfollow has no effect on an owner's delivery class** — `isThresholdFact` only consults the `owner` boolean. Evidence: a non-following owner got 0 notices; the accountable is *already* auto-followed at Task creation yet still only gets threshold; after unfollow the accountable gets 0. Therefore the user's proposed auto-follow fix would not work on its own (and would violate the documented rule that following is the Member's explicit choice), so I recommended changing the delivery judgment input instead.

   **Solved — Round 4 understanding:** Confirmed and restated the user's two-layer model (attention decides delivery; identity only sets default attention). Identified four hard problems: (①) a泛泛 Project owner currently derives unread by identity with no attention — attention-only would blind it; (②) Main stream still uses `ownerSinceFrom` and must be merged or the split persists; (③) executor unfollow conflicts with an active Claim; (④) whether threshold survives at all.

   **In progress — Round 5 research:** Deep research complete. Key new finding beyond my earlier analysis: `project-ownership-model/spec.md` contradicts itself (§1 says Attention decides who receives ordinary Thread updates; §7 makes owner/accountable threshold regardless of attention; §6.1 auto-follows the accountable only to deliver threshold), and the origin is `materials/2026-10-22-inbox-delivery-model.md` §2.1 treating `recipient role` and `delivery class` as separate fields.
