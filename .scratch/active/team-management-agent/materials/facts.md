# issue #64 与当前 Team 行为（2026-11-13，Team 0.2.8 / `4a233446`）

[issue #64](https://github.com/Contexera/dsh-agent-team/issues/64) 请求模板和批量添加成员，报告跨 Workspace 引入后还在沿用原会话。维护者解释引入是让同一个 Agent 跨 Workspace 工作，提出由一个 Agent 创建并管理全局 Agent。当前设计承接后一个提议。

| 现有行为 | 对设计的影响 | 证据 |
| --- | --- | --- |
| 引入只改变 Workspace 参与，不创建或移动 Session；同名 handle 可存在于参与范围不重叠的 Workspace；现有 `memberTarget` 先按 handle 全局取第一个命中，原始 `member:` 字符串也直接透传。 | 组建新团队用创建，复用现有成员要确认目标 Workspace 和稳定 branded member ref，不能给管理会话复用 `memberTarget`。 | [领域模型](../../../../docs/domain-model.md)、`ledger.ts` 的 `joinWorkspace` 与 handle 校验、`packages/tool-agent-team/src/member-target.ts` |
| Web 创建显式选模型，固定传 `team-member`。Host `addMember` 与账本当前不校验 preset 白名单，提交后才在 `activateMember` 失败（`validateMemberPreset` 要求全部 10 个成员工具），且激活失败被吞成诊断，成员记录仍留在账本。 | 管理工具只提供 `team-member`；模型目录沿用 Session controller 的 `modelCatalog()`。现有成员创建入口必须在写账本前拒绝 `team-owner` 和未知 preset，否则会留下无法用作成员也无删除工具的账本记录。已创建与已激活分别报告。 | `TeamAgentsPanel.tsx`、Client `index.ts` 的 `loadModels`、Host `index.ts` 的 `addMember` / `activateMember`、`member-runtime.ts` 的 `AGENT_TEAM_TOOL_NAMES` |
| Host 当前 `assertModelRoute` 主要校验 provider 注册和部分 effort，且在 `addMember`/`updateMember` 中跑在 `ledger.hasCommitted(requestId)` 幂等判断之前；重放会重新跑 provider 校验。 | 管理工具在确认 `requestId` 未提交后再用 `sessionController.modelCatalog()` 核对新指定的路线，区分未知路线和目录失败；已提交回执的重放不重新受此检查。 | Host `index.ts` 的 `addMember`、`updateMember`、`assertModelRoute`；Harness `packages/api/session-controller/src/catalog.ts` |
| `createProject` 支持初始成员：账本只要求 `enabled`，但 Host `assertProjectMembersAvailable` 额外要求运行态 `availability === 'active'`；撤掉 owner 与退出 Project 是两件事。 | 先建成员，只将激活成功的成员随 `createProject` 纳入，最后授予 owner；授予只要求目标 Workspace 参与和合格的状态，授予本身也构成 Project 参与；v3+ 账本下撤 owner 只在失去最后一种参与时交回开放 Task。 | Host `index.ts` 的 `assertProjectMembersAvailable`，`ledger.ts` 的 `createProject`、`projectOwnerChangeProblem`、`accountabilityReturnsFrom` |
| 当前 Project owner 关系只有成员集合，没有每个 owner 在该 Project 中的责任字段；`changeProjectOwner` 只支持 `team/project-owner-added` / `removed`，没有 update 操作。授予会写公共 Activity、给新 owner 留 Main 标记并走提交通知。现有 `team_dm` 只允许同 Workspace 的 enabled Agent Member 互发，Human 不能被 DM，管理 Session 又不是 Member。 | 扩展 owner 关系的 `responsibility`，并新增只追加的更新操作；进入 `team_view` / `team_overview` 和 ownership context；标准交接复用授予通知与持久责任，不直接把 `team_dm` 套给 Team owner。双向管理 DM 若未来需要，另定发送者、回复和离线语义。 | `types/operations.ts` 的 `team/project-owner-added`、`ledger.ts` 的 `changeProjectOwner` / `sendDm`、Host `index.ts` 的 `addProjectOwner` / `dmForAgent`、`member-context.ts` |
| Human Remote 的成员更新要求必填 `handle` 和 `description`；另有 Member 会话 `request/header` 的 `adoptMemberRouteFromRequest` 绕过 `enqueueLifecycle`，用调用前快照直接写账本，可能覆盖并发改名。 | 工具的局部更新在 Host 的 `enqueueLifecycle` 队列内读取当前成员并只合并指定字段（`request/header` 回写也一并串行合并），不能拿调用前旧快照补齐；能力更新报告已保存但还没应用的结果。 | `types/requests-results.ts` 的 `AgentTeamUpdateMemberRequest`、Host `index.ts` 的 `updateMember` 与 `adoptMemberRouteFromRequest` |
| 暂停与恢复是现有 Host 操作，当前没有 Web Remote 或按钮；Project 改名/归档（`updateProject` / `archiveProject`）与成员手动恢复（`recoverMember`）已有公开 Host 方法。`updateProject` 当前要求 `name` 和 `description` 两个字段并全量覆盖；`recoverMember` 要求 `workspaceId` 并校验参与关系。 | `member_state` 复用 `suspendMember` / `resumeMember` / `archiveMember` 并纳入运行态 `recoverMember`；`project_update` 复用 `updateProject`，但要把请求改为可选字段并在账本队列内合并；`archiveProject` 含停清 Project 订阅私有状态。 | Host `index.ts` 的 `suspendMember` / `resumeMember` / `updateProject` / `archiveProject` / `recoverMember`；Client `index.ts` 的 Remote 绑定 |
| 永久移除是 Host 内部操作，会删成员的私有目录。Web Client 没有永久移除 Remote 或按钮；归档保留数据。 | 不提供永久移除工具，也不能把 Human 指向不存在的 Web 操作；归档是 `member_state` 的常规操作。 | Host `index.ts` 的 `removeMember`、`archiveMember`，Client `TeamAgentsPanel.tsx` |
| 成员鉴权绑定 Host 持有的活 Agent；`enqueueAddition(requestId)` 与 `enqueueLifecycle(memberId)` 是两张独立的串行表，且账本对 Human actor 不校验调用者身份。`addMember` 的激活和启动恢复不在生命周期链里，`activateMember` 写回 `handles` 前不重读账本。 | 管理权限也绑定当前活 Agent，在进入账本写入临界区时重检管理会话未被替换且未归档；`activateMember` 写回 `handles` 前重读成员账本状态，防止创建激活途中并发归档留下活句柄。 | Host `index.ts` 的 `memberForAgent`、`enqueueLifecycle` / `enqueueAddition`、`activateMember`，`ledger.ts` 的 `assertHumanActor` |
| 0.2.8 增加 profile 级 `extraToolGrants`：按精确 Host 工具名授权，读在每次 `turn/start`，Team 工具与 `working_directory` 保留，作用于该 profile 的每个 Member。 | 管理会话不是 Member，不继承 `extraToolGrants`；`team-owner` 的 guard 只放行 preset 基线、`working_directory` 和九个管理工具。 | `docs/architecture/tools-and-preset.md`、`member-runtime.ts` 的工具策略、Host `extraToolGrants()` |
