# 03 — 共享读取与过期响应保护

**What to build:** 页面和侧栏读取相同数据时共享一次读取；连续变化、网络抖动和切换页面不会让旧响应覆盖新结果，也不会因请求合并而遗漏最终更新。
**Blocked by:** None — can start immediately
**Status:** ready

- [ ] 先复现成员列表第二次请求的新结果被第一次请求的旧结果覆盖，再验证列表、presence 与 Session 绑定不会回退。
- [ ] 明确查询身份与生命周期，覆盖 Workspace、Thread、分页参数及 Host / Session 代际；先检查 Harness 和现有依赖的能力，再决定是否需要查询库。
- [ ] 同一数据查询的多个消费者共享进行中的读取；连续变化可以合并，但在途请求期间的新变化仍得到后续刷新。
- [ ] presence 变化只读取成员运行状态，不重拉 Thread 内容或频道消息；Thread、Channel、Workspace、全局 Inbox 各范围按实际受影响的数据刷新。
- [ ] 首次订阅和重连基线仍触发有效读取，即使版本相同或降低；保留订阅关闭与插件卸载的清理语义。
- [ ] 过期响应、已离开页面的响应、失败读取和取消不会更新错误的查询或伪装成空数据；动作错误与背景刷新失败可区分。
- [ ] 为重复读取和丢弃过期响应留下按查询关联的诊断与计数，避免记录响应正文。
- [ ] 整理 Channel、Thread、Agents、Inbox 等消费者，移除被替代的手写刷新流程，不保留两套查询所有权。
- [ ] 验证草稿、焦点、导航和普通 DSH 恢复；查明已有渲染检查中的 WeakMap 错误，按适用范围运行组件检查和真实浏览器验收。
