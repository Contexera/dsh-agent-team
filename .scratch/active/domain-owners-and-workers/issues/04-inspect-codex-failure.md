# 04 — 按执行编号只读查看 Codex 失败

**What to build:** Codex Worker 失败后，发起成员和 Human 用 Team 执行编号查看失败摘要、可用的原生 ID 和相关历史片段，原生进程退出后仍可查询。
**Blocked by:** 02 — 原 Thread 留结果，发起者收到 Inbox 通知
**Status:** pending

- [ ] 对已打开的原生会话保留可定位的原生 thread ID、该次 turn 归属与原生存储位置；在还没有 ID 时失败，明确说明失败阶段和没有会话可查。进程退出前提取有界安全诊断，关闭句柄后仍能按 Team 编号查到。
- [ ] 对两个并行执行在不同原生记录中制造不同失败，反序查阅时只返回对应片段。查询沿用原来的原生存储位置；记录缺失、尚未落盘或版本不支持时保留 Team 摘要并说明原因。
- [ ] 使用发布的 Codex CLI 实测退出后的只读历史，不加载会话续聊、不启动新的模型请求。不要扫描最新文件或接受任意原生会话 ID。
- [ ] 普通 Thread 只见结果和必要摘要；只有有权的发起成员及 Human 能按编号查看更具体的诊断。绑定与临时执行均可查，不保存或公开完整原生记录、凭证或原始协议载荷。
