# 01 — 在 Team 设置放行和撤销宿主工具

**What to build:** Human 在当前 DSH profile 的 Team 设置中搜索、多选已注册的宿主全局工具并保存。这个 profile 中的 Team 成员从原会话的下一轮开始使用新名单，无需重启。

**Blocked by:** 公开接口必须能验证成员当步使用的是原全局注册，包括与成员 scope 共用同一个定义对象的情况；见[开工条件](../spec.md#开工条件)。

**Status:** pending

- [ ] 默认名单为空。可按确切工具名搜索、多选、保存和取消改动；已选但未注册或已冲突的名称仍可见、可移除。列出的是 Host 全局注册，当前未注册和加载失败可区分，不安装或重新挂载插件，不推断插件来源。
- [ ] profile 持久化一份统一名单。已有白名单的成员也可使用已选外部工具，但不能靠自己的白名单放行外部工具；原有工具优先，禁用的 preset 工具不会因同名全局注册而重新开放。重启及成员恢复、换代后按当前 profile 读取；另一个 profile 和普通 DSH 会话不受此次保存影响。
- [ ] 在同一会话用真实 DSH 工具执行链路和模拟模型验证：未选全局工具既不声明也不能直接或经 DSH 管道嵌套调用；保存后能调用，撤销后不能声明或调用。保存过程中仍在执行的回合保留开轮时的名单；下轮第一条请求读取开轮前已生效的最新名单，包括连续两轮之间不空闲的情况。工具变化由 DSH 正常记录，不额外注入提示或唤醒成员；保持 Team 的 Native 模式。
- [ ] 原全局注册的激活条件、DSH 权限和成员 Agent 身份仍生效。验证条件为假、DSH 拒绝及迟到注册；在准备模型步骤后卸载或重注册（包括复用同一对象）不能接管该步骤，新步骤可按当轮名单使用当前原全局注册。不同定义和同一对象的成员 scope 同名注册均不能借放行获得执行权；缺少步骤准入的调用也不能绕过原条件。
- [ ] 模拟成员应用失败：已保存的撤销在下一轮不能被旧授权恢复，原有工具能安全保留；若原有工具限制也无法确认，则该轮不发模型请求。修复后下一次正常开轮重试。
- [ ] 在组装后的 Web 验证搜索、多选、取消、保存、清空、目录读取失败、Human 身份读取失败时仍能撤销、缺失工具和键盘操作，检查桌面与窄屏。验证名单读取失败时禁止提交、写入失败时保留草稿；第二个页面撤销后，旧草稿保存遇到版本冲突，不恢复已撤销授权。保存成功提示只承诺配置已保存。
- [ ] 用至少一个实际安装的插件核对成员调用者、工作目录及目标资源。更新用户配置说明和工具范围文档，说明所有成员共享放行、同名新注册可能取得授权、插件权限与提示注入限制。
