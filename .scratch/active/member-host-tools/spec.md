# Team 成员按需使用宿主插件工具

宿主插件可以给成员注入简报，但其全局工具默认不进入成员工具清单。[#82](https://github.com/Contexera/dsh-agent-team/issues/82) 的用户希望在同一成员会话调用 `project_*` 等已安装的工具，不用改插件或复制 Team preset。首版由 Human 按工具名显式放行。

## 设置

Team 设置在当前 DSH profile 下保存一份统一名单，默认空，适用于这个 profile 中运行的所有 Team 成员。成员自己的工具白名单继续收窄原有工具，不能放行外部工具，也不限制 profile 已放行的外部工具。原有 Team、preset 和显式共享的工具优先；即使某个 preset 工具被成员白名单禁用，也不能通过同名宿主工具重新开放。

```text
Team 设置 · 外部工具
适用于当前 profile 的所有 Team 成员
按工具名放行；同名工具换了提供方仍会按这个名字授权。
搜索工具名：[project_             ]
[x] project_list
[ ] project_update
[x] project_archive    当前未注册
                       [取消改动] [保存]
```

- 从 Host 当前全局注册表读取可选名称，按工具名搜索并多选；按当前 Team preset 和共享工具去重。运行时仍按每个成员实际绑定的 preset 排除重名，不能只信设置页的目录。
- 已选但当前不可用的名称仍可查看和移除，包括插件停用或和成员原有工具重名。注册目录不代表特定成员在某轮可以调用；插件的激活条件仍生效。目录加载、读取失败和搜索无结果各有独立状态；目录失败时仍可移除已读取的已选名称；名单本身读取失败时不允许按空名单保存。外部工具设置独立于 Human 姓名、头像的读取；后者失败不影响撤销。
- 沿用 DSH profile 设置权限：具有 profile 配置权限的 owner 能保存；普通成员工具没有设置入口。仅写名单字段。草稿和已保存名单分开，按草稿开始时读取的版本保存。失败保留草稿；发生版本冲突时先显示最新名单，由用户核对后再保存，不能自动提交旧草稿。保存的是确切、区分大小写的名字；从目录选中的工具在保存前消失时，该名称保存后显示为未注册。撤销某名就是从名单移除它；保存空名单明确撤销全部。
- 首版不安装或重新挂载插件，不做按插件自动分组，不猜工具的提供方，不维护兼容名单。授权随名字保留，重启或卸载后若有同名工具重新注册，之后的步骤可以使用它。用户负责选择可信提供方及验证兼容性。

## 生效与执行

- 以 Host 有效配置提交和成员 Session 的 `turn/start` 排序。每轮在第一次工具解析前同步读取最新有效名单；已经开始的一轮保留当轮名单，连续两轮不空闲也适用。保存成功表示配置已保存，不表示所有成员已应用。新建、恢复和换代读取同一配置，不为设置变化唤醒成员。
- Host 在成员原有工具策略上附加当轮已放行的宿主全局工具；运行态不建立第二份持久名单、不改 Team 账本。卸载可立刻使尚未执行的调用失效，不承诺中断已开始的调用。当步只接受 DSH 为该步骤准入的原注册，即使同一个定义对象被注销后重新注册，旧步骤也不能使用它。新步骤用当轮名单和当前注册重新判断；已选工具后来才注册也要走同一判断。
- 在现有 Native 模式中，模型直接调用和经 DSH 管道发起的嵌套调用都保留原全局注册的激活条件、DSH 原有权限及审计身份，以成员 Agent 执行。禁止成员或 preset scope 用同名注册顶替全局注册，包括两个作用域复用同一个定义对象。调用必须受当步准入约束；缺少当步准入信息的外部工具调用不能作为绕过条件的入口。首版不为 Team 成员开启 Code Mode（PTC）。
- 若当前轮的限制更新失败，记录原因并降级到原有成员工具，不能恢复含已撤销授权的旧限制。若连原有工具限制也无法确认，阻止该轮发出模型请求，下一次正常开轮时重试。已保存的设置不因某个成员失败而回滚。
- 工具变化沿用 DSH 请求记录，不额外发提示。既有成员 scope 工具可能被模型看见但调用会被拒绝；本功能不改变这一声明边界，也不过滤插件注入的提示。放行会让所有成员能通过插件原有身份和权限访问资源；Team 不替插件限制工作区或加逐次确认。工具结果仍是外部输入。普通 DSH 会话和非成员 Agent 保持原行为。

## 开工条件

DSH `0.2.2-rc.1` 的公开工具查询只能比对定义对象，不能确定某个步骤准入的是宿主全局注册还是复用同一对象的成员 scope 注册。已实测后者可以绕过全局注册的 `when: false`。DSH 会拦同一模型步骤内的注册替换；这项保护不能代替验证步骤一开始选中的是哪个作用域的注册。

按现有设计，先找到可稳定验证「当步使用原全局注册」的公开接口；优先考虑上游暴露注册作用域或等价的准入信息，不需要插件来源 ID。若决定在现有版本先交付，需由 Human 明确接受同一对象重注册可能绕过全局条件，再修改执行承诺和验收。未决定前，实施票保持 pending。详见[源码与复现](materials/feasibility.md#原注册与同对象遮蔽)。

## 验收

[实施票](issues/01-allow-host-tools.md)覆盖完整设置与调用路径。用 DSH 实际注册和执行链路、可控插件及模拟模型断言声明与执行结果；至少用一个实际安装的宿主插件验证成员 Agent、工作目录和资源落点。若无法确定 #82 的插件身份，使用另一个已知插件，不能据此宣称 #82 的具体插件已兼容。最后在组装后的 Web 验证设置流程、两页并发、键盘和窄屏。
