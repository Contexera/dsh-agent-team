# Team 成员按需使用宿主插件工具

[#82](https://github.com/Contexera/dsh-agent-team/issues/82) 的核心需求是：其他已启用插件注册的工具被 Team preset 的限制过滤后，Human 可在 Team 设置显式放行，让成员在原会话使用。2026-11-10 19:05 Human 确认按这个目标实施，并要求设置页先读取可选工具。

本版采用已验证的**额外工具名称许可**，取代原 PR 要求的“锁定原宿主全局注册”。原始接口局限及对照实验留在 [研究记录](materials/2026-11-10-registration-contract.md)和[名称许可原型](materials/2026-11-10-name-grant.md)，不修改 Harness。

## 设置

当前 DSH profile 保存一份名单，默认空，适用于该 profile 的所有 Team Member。它在成员原有工具策略之外追加名称许可：Member 白名单仍收窄原有工具，但不能覆盖 profile 对同名工具的明确放行。授权随工具名称保留，而非某个插件、定义对象或注册实例。

```text
Team 设置 · 额外工具
适用于当前 profile 的所有 Team Member，下一轮生效
按工具名放行；同名工具按 DSH 的作用域规则选择。
搜索工具名：[project_             ]
[x] project_list
[ ] project_update
[x] project_archive    当前未注册
                       [取消改动] [保存]
```

- 从 Host 全局注册与 live Agent scope 注册中读取已注册名称，按确切工具名搜索与多选；不推断插件来源、不按插件分组、不克隆或重新挂载插件。目录用于发现可放行的宿主名称，排除已激活 Member preset 的基线工具，不声称是每一个 Member 当轮“被过滤工具”的精确快照；成员可能绑定不同 preset 或 scope 注册。Team 工具及 `working_directory` 不作为额外许可候选，不能借名单绕过 Worker 开关。
- 已选而当前未注册的名称仍可见、可移除。目录不保证特定成员当轮可调用，所选注册的激活条件仍生效。目录加载、失败和搜索无结果分别显示；目录失败不阻止移除已读取的选择；名单读取失败禁止按空名单保存。该组独立于 Human 姓名／头像读取，后者失败不能挡撤销。
- 沿用 DSH profile 设置权限及版本事务，只写名单字段。草稿与已保存值分开，使用开始编辑时的版本保存。失败保留草稿；版本冲突后显示最新名单，等待用户核对再保存，禁止自动重放旧草稿。名字确切、区分大小写；保存前名称消失可保留为“当前未注册”。清空保存显式空数组，不用 unset 恢复下层授权。
- 保存提示只说配置已保存、下轮生效，不说所有 Member 已应用。不增加模型工具设置入口，不向 Team 账本写名单，不因设置变化唤醒成员。普通 Session、其他 profile 不受影响。

## 生效与执行

- 以有效配置提交与每个 Session 的 `turn/start` 排序。每轮首次工具解析前同步读取并冻结最新有效名单；已经开始的回合保留其名单，连续两轮不经过 idle 也成立。创建、恢复、换代均读取同一配置，不重建已有 Session。
- 对已许可名称，接受 DSH 为该 Member 和步骤解析并准入的注册。同名近层优先，同定义对象／不同定义对象均如此；不承诺用宿主原件，也不让远层注册的 `when` 约束另一份独立注册。profile 的明确名称许可可以重新允许 Member 白名单未包含的同名能力；Team 必需工具、`working_directory` 及 Worker 开关独立保护。
- 保留实际选中注册自己的激活条件、DSH 执行前检查、成员 Agent 身份、直接及嵌套调用的当步准入。无当步准入或别的 Agent 复用准入时拒绝额外能力。准备步骤后注销／替换（包括同对象重新注册）使旧准入失效；下一步按当轮名单和当前注册重新判断。已选名称迟到注册也须能刷新声明限制并进入后续正常步骤。
- 保持 Native 模式，不为 Team 开启 Code Mode（PTC），不增加替代执行器、复制注册或模型可调用的策略绕过入口。工具变化沿用 DSH 请求记录；除下述可见但未授权工具的动态警示外，不增加额外提示注入。
- 应用失败时先收紧为无额外许可的原有成员基线，不能回滚到含已撤销名称的旧限制。若连基线限制也无法确认，则该轮不发模型请求；下次正常开轮重试。某 Member 应用失败不撤回已保存设置。
- 撤销在下一轮生效，不承诺停止已执行的调用；插件卸载可使尚未执行的已准备调用失效。未放行的继承全局工具不声明且拒绝执行；Member 自有作用域工具可能仍被声明，但不因出现于目录而获得执行许可；Host 在条件式 prompt section 中列出这些可见但未许可的名称并禁止调用，许可从下一轮生效后撤出。若 Harness 以后提供自有 scope 的声明过滤接口，可改为隐藏 schema，执行 guard 仍保留。此功能不修复既有基线分类缺陷或其他插件的提示注入。

## 已知边界与非目标

首版是 profile 统一许可，不提供每个 Member 对新增许可的二次否决，不锁插件来源，不安装插件。实际插件仍可能依赖 Session、cwd 或其他资源条件；名单只解除 Team 的工具限制，不替插件建立资源授权，也不绕过 DSH 审批／sandbox。全局与近层同名注册发生变化时，授权随名字而非提供方。
