# 01 — 在 Team 设置放行和撤销额外工具

**What to build:** Human 在当前 DSH profile 的 Team 设置中读取、搜索、多选已注册的宿主工具名并保存。所有 Team Member 从原会话下一轮开始获得这份额外名称许可，取消后撤销，不需重建成员或重启。

**Blocked by:** None — Human 已确认按额外工具名称许可实现，公开接口的原注册归属缺口不再属于此方案前提。

**Status:** complete

- [x] 默认空名单，按确切名称搜索、多选、保存、取消及清空；已选但未注册名称可见且可移除。目录只通过公开视图发现名称，不推断插件来源或伪称逐 Member 精确过滤快照；不重挂插件。Team 必需工具及 `working_directory` 不作为增权候选。
- [x] profile 持久化统一名单，只修改名单字段；不写 Team 账本。成员自身白名单不能自行放行外部名称，但 profile 明确放行可覆盖同名 Member 禁用。Team 必需能力及 Worker 开关保持原规则。其他 profile、普通 Session 不变。
- [x] 真实 DSH + 模拟模型验证未选工具不声明、不直接／嵌套执行；保存后可用、撤销后拒绝。同轮保持开轮名单；下轮首次模型请求使用最新有效名单，包括连续两轮无 idle。创建、恢复、换代同样生效，不因设置变化唤醒成员。
- [x] 所选注册自己的激活条件、DSH 执行前拒绝、成员调用身份及嵌套 parent 准入保留。global／Team 组／preset／Member scope 的同对象及不同对象重名按 DSH 正常选择，不锁宿主原件。缺失当步准入、别的 Agent 复用准入均拒绝。
- [x] 准备模型步骤后卸载／同对象或不同对象重注册不能接管旧步骤；下一步可按当轮许可选择当前注册。迟到注册的已选名称可进入后续正常步骤的声明，不只在 guard 中放行。
- [x] 应用失败不能恢复旧额外授权；安全回退为原有基线。连基线限制也失败则零模型请求；下次正常开轮可重试。Member 自有作用域的未授权工具可能仍声明，但不得获执行权；条件式 prompt section 精确列出这些名称，许可生效后撤出。
- [x] 组装 Web 覆盖读取、搜索、多选、取消、保存、清空、缺失工具、目录失败、名单失败、写失败与 Human 身份失败下的撤销。两页面版本冲突必须显示最新值、保留待核对草稿且不自动恢复已撤销许可。桌面／390×844 无溢出，键盘及状态反馈有效。
