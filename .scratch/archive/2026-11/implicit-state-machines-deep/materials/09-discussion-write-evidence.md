# 讨论切换与晚到写入

```text
[A：正在发送]  -- 切换 -->  [B：可以编辑、发送]
        A 的回执 -------->  只处理 A，不清 B 的稿、不改变 B 的页面
```

Host 决定写入结果。讨论侧栏内切换时，写入仍属于原 Thread；能更新消息、报错和导航的是发起写入的那次打开。重新打开同一个 Thread 不接收上次打开的回调。回复确认后用提交时的草稿快照做比对，仅清理未编辑的原草稿。

| 路径 | 复现及验证 |
| --- | --- |
| 08 回复 | 改动前 A 的发送状态把 B 的输入框设为只读。延迟 A 的成功或失败，验证 B 可开始自己的发送，A 不能解除 B 的发送状态、改 B 的内容或报错。A→B→A 时原发送仍在途；完全关闭再打开后的新编辑不会被旧回执清除。 |
| 09 转 Task | 改动前 A 的成功回执会把 B 跳到 Task。验证 A 的成功和失败均不劫持 B，两个请求的身份独立，已提交的 Task 仍出现在 Project；原页正常成功仍打开 Task。 |
| 10 关注 | 延迟关注写入、失败和关注者读取，核对 B 的按钮不会反映 A 的状态。再打开 A 时从当前读取收敛；一次确认成功不会因随后的读取失败而消失。 |
| 12 完全关闭再重开 | Client 探针验证重发使用新请求 ID 和较新 revision。真实 Web 探针只暂扣首个成功回执，关闭、重开并重发后，两个请求均提交成功，Host 历史出现两条相同回复。 |

二审核对了 Worker 启动时 stop、晚到句柄和 Webhook 关停。已有故障注入覆盖各自的恢复边界；没有证据要求另建组合状态或增加票据。通知上限保留为 [11](../issues/11-notice-overflow-evidence.md) 的证据项。

最终全量测试 2,675 项通过、1 项跳过；类型检查、lint、文档和界面规范检查通过。最终构建的 24 项正式浏览器用例通过，检查了桌面 1440×960 和窄屏 390×844 的讨论侧栏。用于复现 12 的临时探针已删除。
