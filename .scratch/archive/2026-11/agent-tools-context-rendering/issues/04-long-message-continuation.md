# 04 — 长消息能续读，完整提供前不确认

**What to build:** Thread/Main 的长消息通过现有 team_thread read/message 连续读取；输出有界、每步能前进，完整交付后按 read 或查询的性质处理确认。实现 F6，不增加第八个工具。
**Blocked by:** 03
**Status:** complete

Thread/Main read 与 message 复用同一缺段续读规则；真实 Session 覆盖中文/emoji逐字拼接、中段丢失、单独末段、无未读长背景、查询后read省略确认、后续消息不跨过未完整消息、容量拒绝。Session restore 与新旧 ledger receipt replay 分别验证；没有付费模型评测。

- [x] 普通消息仍尽量全文；批次先减少条数，单条确实放不下才分段。预算包含外层文字、状态及续读入口。
- [x] 用一个系统提供的续读方式推进不可变消息，明确消息身份、当前片段、是否结束；不让模型选择多套 offset/limit 协议。
- [x] read 续读完整后确认对应事实；message 续读不确认，后续 read 可确认且不重复正文。未完整的消息不能被跨过而推进连续已读水位。
- [x] 新接口在选择批次时确定确认范围；当前 Session 的片段可见性不成为 ledger replay 依赖，旧读记录重放不变。
- [x] 精确覆盖整段正文，不因多字节字符或分割边界丢字；截断通知、末段单独存在、当前 surface 缺段均不能冒充完整。
- [x] 正常连续读取有进展，中断后可以继续；裁剪/压缩缺段时明确补读，不反复返同一开头或错误确认。实际超出模型可承载容量时明确限制，不假装已读完。
- [x] 对消息附件只给读取入口，不把消息全文等同附件全文；不新增通用大文件系统或备用无限输出路径。
- [x] F6 真实工具/Session/Host 流程通过，含没有未读的 message 查询、长消息后跟新消息、Thread/Main、重启重放。更新类型、tool 说明、双语正式文档和 CHANGELOG；按 Remote 影响执行相应检查。
