# 05 — 验证带附件消息在响应丢失后可安全重试

**What to build:** 验证附件上传成功但发送结果不确定时，用户用原输入重试同一次发送，最终只出现一条消息且附件仍可打开。

**Blocked by:** 无。

**Status:** complete

- [x] 从 Main stream 发消息、同一编辑器开 Thread（含 Task 选项）及 Thread 回复验证：提交未到达 Host，以及 Host 已提交但响应丢失。覆盖 Remote 返回错误和调用抛异常；Thread 收到已提交消息的刷新后再重试。
- [x] 结果不确定时沿用原提交及完整请求（含目标、发消息或开 Thread 的模式、Thread 原修订和有序附件引用）。部分上传成功或上传响应丢失时，原文件沿用各自上传标识，已取得的引用可直接复用。明确改动正文、附件、模式或回复目标才创建新意图；收到未读或修订拒绝后，仍按当前流程读取，再由用户发起新提交。
- [x] 在同一编辑器仍打开、缓存仍有效时，未修改的重试只提交一次，并可打开同一附件；保留 Host 权限和修订校验。离开或重新加载后先查看历史，不自动恢复或重发这次意图。缓存已到期或身份、目标等条件变化而被 Host 拒绝时，如实提示。上传失败保留输入，未引用文件按现有清理契约处理。
- [x] 组装 Web 直接丢弃已提交的 Main stream 回执，两次调用的业务请求和回执一致，Host 只有一条消息和一个缓存条目；附件仍可用键盘打开。其余分支通过挂载的 Client 回归测试。
