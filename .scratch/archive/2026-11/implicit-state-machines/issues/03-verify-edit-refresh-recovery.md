# 03 — 验证编辑保存后的刷新恢复

**What to build:** 验证 Agent 或 Project 编辑已经在 Host 保存、后续列表刷新失败时，用户能看到真实状态并恢复列表，不会被引导重新提交同一次写入。

**Blocked by:** 无。

**Status:** complete

- [x] 从实际 Agent 和 Project 编辑对话框验证：保存确认后，列表读取返回 Remote 错误时，检查弹窗关闭后的列表错误和重读入口；另注入读取调用抛异常，检查是否被显示为保存失败。Project 面板分别验证项目列表与成员列表单独失败；成功的一侧仍更新。
- [x] 若复现，在共用保存流程中把 Host 已确认保存与列表刷新结果分开。已保存后的恢复只重读，用户可关闭弹窗；无需把已有的列表错误搬进弹窗。Host 明确拒绝时保留表单；写入结果不确定时，原输入的重试沿用原请求标识。保留现有权限、确认和版本校验。
- [x] 保存后令一次刷新与正常更新通知交错：被较新读取取代的响应不报错、不覆盖新数据。记录用户看到的新值和实际 Host 写入次数。
- [x] 若修改交互，按 [Web 验收要求](../spec.md#范围与决策) 验证成功、写失败、刷新失败和关闭后的焦点。

验收：组装 Web 通过键盘编辑 Agent，Host 保存后故意断开列表读取。弹窗关闭、焦点回到原行，列表显示保存已确认；用键盘重读显示新名称，Host 写入调用总数为 1。已挂载的两个编辑面板覆盖拒绝、不确定写入、部分读取成功和迟到响应。
