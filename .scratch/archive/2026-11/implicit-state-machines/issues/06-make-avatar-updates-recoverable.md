# 06 — 让换头像和移除头像可恢复

**What to build:** 设置页换头像或移除头像时，Host 完成整次操作。保存被拒绝时，原头像仍可读；配置已经保存时，后续刷新或文件清理失败不会把它显示成「没有保存」。

**Blocked by:** 无。与 02 的头像读取降级可独立验证。

**Status:** complete

- [x] 先封住现有文件入口：由 Host 验证头像引用和实际文件位置，直接通过 Remote 验证不合法或指向目录外的引用不会读取或删除文件。保留实际旧版本生成的合法引用。此项可先于设置交互改动验收。
- [x] 先复现两条路径：新图片已上传、头像引用写入失败；移除图片后、清除引用失败。检查设置中的引用、原图片和新增文件，区分拒绝写入与写入已提交但响应丢失。
- [x] 设置页发一次换图或移除意图。Host 准备好完整图片才切换引用，使用 Harness 设置写入的版本校验；旧快照的请求遇到更新时提示重读。移除必须实际显示文字头像，不能因继承层补回或重启迁移重新采用旧引用而误报成功；设置不可写时保留原值。移除可直接写任意头像引用或删除文件的分步入口，保留姓名编辑。
- [x] 验证两窗口交错换图与移除，及响应丢失后另一窗口又修改的情形。结果不确定时先重读当前设置；无法确认原请求结果就说明不确定，用户重读后可以发起新操作。旧请求不能自动重放；设置版本是进程内事实，重连或重启后必须重新读取再修改。
- [x] 首版保留曾被引用的图片及提交结果不确定的图片。同一 DSH home 的其他 profile 或继承层可能仍引用它们；仅清理本次生成且已确认未提交的新文件，清理失败不改变保存结果。
- [x] 通过实际设置入口验证换图成功、拒绝保留原头像、继承层与旧设置迁移、提交后的刷新失败、清理失败和两个 profile 先后打开同一 DSH home。提交前启动的身份读取即使较晚返回，也不能替代提交后的重读。更新 Host 权威文档；如有可见交互变化，按 [Web 验收要求](../spec.md#范围与决策) 验证。

验收：真实 Web 的两个设置窗口验证旧版本写入被拒；丢弃已提交的换图响应后，另一窗口移除，第一窗口只有一次换图请求，显式重读后显示首字。用两个命名的 CLI profile 先后打开同一个临时 DSH home：A 在设置中换图，B 用独立设置记录引用同一张图、读到后移除，重开 A 仍显示原图。Host 测试也覆盖这条路径、设置拒绝、结果不确定、清理失败和旧设置迁移。
