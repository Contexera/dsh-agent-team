# 04 — 验证时间线阅读位置不会跳动

**What to build:** 在真实浏览器验证：用户在 Thread 或 Main stream 读旧消息时，尾部收到新消息或头部加载更早的历史，当前可见消息仍留在原来的阅读位置。

**Blocked by:** 无。

**Status:** complete

- [x] 在桌面和 390×844 的两个入口，用同一条稳定消息相对滚动容器顶部的位置作对照，分别触发尾部到达、头部补页、补页期间尾部到达。记录浏览器版本和位置变化，截图只作辅证。覆盖长消息和图片占位，区分插入内容与图片加载完成造成的高度变化。
- [x] 若复现，在现有时间线保留读者正在看的消息与位置，不用整个列表的高度增量推断头部插入量。浏览器已经保持位置时不重复补偿；位于底部仍跟随新消息，主动跳转优先，历史加载失败可重试。通过原有读路径验证 Host 已读行为不变。
- [x] 若修改交互，按 [Web 验收要求](../spec.md#范围与决策) 验证。

验收：Chrome `157.0.8103.39`，桌面 1440×960、窄屏 390×844。Main 与 Thread 共 16 次位置测量；14 次阅读锚点位移为 0px，另 2 次跟随新消息后距底部 0px。基线中上方图片加载使锚点移动 73px；修复后图片高度增加 73px，锚点不动。完整旅程也验证从看板打开未读 Thread 时滚到最新消息并自动确认已读。
