# 07 — 区分附件已过期和读取失败

**What to build:** 读一条已有消息时，图片读取失败仍能看到消息和附件名；用户能分清缓存已无和读取失败，不会把文件损坏或一次读取错误看成永久过期。

**Blocked by:** 无。与 05 的发送重试可独立验证。

**Status:** complete

- [x] 先从实际 Remote 验证：Host 拒绝不合法或指向缓存目录外的附件引用，且不把拒绝报成过期。合法引用仍可预览或附在消息上。此项可先于预览交互改动验收。
- [x] 在实际预览入口分别验证缓存确实已删、读取元数据遇到 I/O 错误、元数据非法、Remote 返回一般错误和读取调用抛异常。记录 Host 返回和 Client 的可见结果；已收到但浏览器解码失败的图片也不能显示为「已过期」或可放大的空图。
- [x] 沿用现有 `team/attachment-not-found`，只用于确认缺失；读取或解析失败保留为错误。Client 缓存可用结果；确认缺失只说明本次没有缓存，不能阻止后续重新读取同一标识。失败保留附件名并提供原地重读，读取时不使用已知解码失败的副本；加载期间不开放空预览。保留半写上传同一请求可收敛和正常缓存淘汰的契约。
- [x] 验证真实图片可打开、缓存到期后重新打开消息仍能读历史、临时失败后同一附件可读，以及破损附件不会阻塞同一消息的其他内容。更新 Remote 失败语义文档；如改可见交互，按 [Web 验收要求](../spec.md#范围与决策) 验证。

验收：同一条历史消息包含两个附件。删掉缓存的附件显示「文件已过期清理」；坏图保留文件名并显示「图片暂不可用」。修复该图的缓存后，键盘重读同一引用，焦点落到可打开的缩略图，Enter 打开、Escape 关闭。
