## 范围与决策

保留 ledger、Session 和 Host 各自的状态权威。行为修复先从真实入口复现；架构优化须说明能消除哪条重复规则，或让调用方不用再协调哪些步骤。新增模块有这类收益才拆；不引入全仓 FSM、平行状态仓、通用异步层或新的外部脚本执行保证。

Webhook 返回 `202` 后，Host 持有该次投递。重试耗尽时，先在原接收记录中持久保存耗尽结果，再写入可供负责人重放的失败记录，最后移除接收记录。耗尽结果落盘后，恢复只完成记录转移，不再自动执行脚本。人工暂停不阻止这项清理，也不放行脚本；删除订阅和归档 Project 保持原有终止语义。保留同一次接收的脚本输入和标识，保留现有失败记录的保留期限与去重规则。

01 的行为回归已通过。发布前必须完成 08：`v0.2.7` 的订阅存储已使用 v4，旧 v4 不能解码新增的耗尽状态。按 Harness `0.2.2-rc.1`（`66491b05`）的存储版本契约，升到 v5、保留 v1–v4 的读取兼容。用 Team 自带的 SQLite 后端验证：兼容打开和读操作不改版本，首次实际修改与版本同事务提交，写入回滚不升级，旧读取器冷开时明确拒绝 v5。首次修改可能由 Host 启动后的后台任务发起；共享 DSH home 的旧 Host 须先停止，回退以升级前备份为准。

建议 08、09 同批发布，只升级一次订阅存储。如果 01 需要先随 08 发布，09 的新持久字段仍须独立做格式兼容判定；已发布的 v5 不能读时，随 09 升到下一版。发布批次不影响 08 开工。

验证票未复现时记录版本、场景和观测结果后结束。凡改动可见 UI 或交互，按仓库要求走组装后的 Web 验收，检查桌面与 390×844、键盘与焦点、相关加载/错误/空态及退出 Team 后普通 DSH 的恢复。

头像和附件的现有文件入口缺少运行时目录边界检查。06、07 先验证并修复 Host 的读写边界，合法的历史引用继续工作；非法引用或目录外目标由 Host 拒绝，不解释为缓存过期。这部分可先于换图和预览交互交付。

## 架构优化

| 优化 | 现有问题 | 建议 |
| --- | --- | --- |
| 头像写入（06） | 浏览器分步写文件和设置；移除先删文件，清除引用失败时会留下坏引用。 | 让 Host 接收一次换图或移除意图，复用 Harness 设置版本校验。确认保存前不改变引用的可读性；响应不确定时只重读当前结果，不自动重放。移除不能被继承层或旧设置迁移撤销。首版只清理本次生成且确认从未提交的文件；当前 profile 不引用不足以证明共享文件可删。 |
| 编辑提交（03） | 两个面板自己处理列表读取返回的错误；读取抛异常时，共用保存流程会在写入已确认后仍进入保存错误分支。 | 用真实入口确认表现。已确认写入后的恢复只重读；保留两个面板各自处理列表与部分结果的方式。写入结果不确定时，未改输入的重试沿用原请求标识。 |
| 消息发送（05） | Main stream 可能把响应失败当成新提交；Thread 回复可能保留标识却重新上传或换用新的修订。两者都可能无法取回原回执。 | 复用发送意图内的上传标识及完整提交请求，包含 Main stream 编辑器的开 Thread/Task 分支。区分结果不确定和 Host 明确拒绝；只在前者原样重试，保留既有权限、未读和修订校验。 |
| 附件读取（07） | Host 已有缺失错误码，但元数据读取异常可能被误判为缺失；Client 也会把其他错误画成过期。 | 保留现有错误码，仅用于确认缺失。附件预览在读取或图片解码失败时保留文件名并提供重读；缓存策略仍由同一个预览模块决定。 |
| Webhook 耗尽收尾（09） | 可重放记录先于失败计数落盘；恢复时会因记录已存在跳过计数。计数达到阈值后，自动暂停也可能尚未提交。 | 先保存本次耗尽的计数归属；计数与已应用证据同一次写入 checkpoint，暂停仍由 ledger 确认。按同一订阅的顺序续办：后来成功清零、人工恢复或定义更新后，旧收尾只保留失败记录，不再增加计数或暂停。旧记录没有进度时不补算历史。 |
| Task 状态（10） | Task 写入、重放和已有的派生函数重复描述结论与 Claim 如何生成状态。 | 只归并这条纯规则。重放从活动推导预期结论，不能拿记录自身的结论证明记录正确；历史验收的通知规则和权限校验仍按原样执行。 |

04 若证实滚动错位，用同一条可见消息相对滚动容器的位置验证恢复，包含补页与新消息同时到达。浏览器已经保持位置时不重复补偿；主动跳转和底部跟随优先于保持旧位置。阅读位置不决定已读。侧栏拖动、模型目录和订阅弹窗暂无独立故障或重复规则需要清除，不单独重构。共享查询、Member 换代与摘要继续由现有模块协调；不额外包一层。

Webhook 队列若实测积压，再区分是每轮重复扫描还是逐个等待导致；分别评估一次扫描、让候选进入现有四槽调度器，不预先加索引或调度器。`running` 没有已知接收记录生产路径，不改兼容契约。更新检查 `off` 按现有方式停止发起请求，只有另行决定关闭也隐藏提示时才改。
