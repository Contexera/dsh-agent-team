# 决策快照：领域负责人和本机 Worker

状态：2026-11-08，#79 首版设计已确认；2026-11-09 票 01、02 已验收，03 已派发给 Tars，04 前置已完成、尚未派发，05/06 仍按依赖等待。本文记录产品决定和验收边界；当前进度见[工作项入口](README.md)，当前行为以源码与测试为准。

2026-11-09 补充决定：两个 CLI 默认以完整权限运行，不要求配置权限；设置页不再提供沙箱选择器。Codex 的显式收紧仍可在配置行声明。02 的公开 Thread 只展示执行/终态与有界安全原因，回答和部分结果走发起者的私有通知；通用受限诊断查看仍在 04。

## 1. 问题和长期方向

Team 中值得长期保留的是对一个领域的持续责任和独立判断。成员围绕人类给出的目标积累项目知识；提醒和 Project 订阅提供下一次判断的时机；成员选择自己做、派 Worker，或就依赖、共享约定和冲突找其他 owner 协调，再以交付反馈修正下一次行动。Worker 提供按需执行，不成为长期成员。领域可以用现有 Project 和 owner 表达，首版不要求增设 Domain 对象。

[#79](https://github.com/Contexera/dsh-agent-team/issues/79) 用这个方向解决一个具体问题：现有 DSH 成员能把独立任务交给本机 Codex 或 Claude Code，自己继续推进其他工作；结果能回到该去的地方。首版为实验功能，默认关闭。

## 2. 设置与权限

- Human 在 Team 设置打开“允许项目负责人委派 Worker”，并选择启用的引擎和默认 Worker。只启用一个时直接用它；启用多个时须指定默认。每次发起可选另一个已启用的引擎。选定引擎不可用时说明原因，不自动改用其他引擎、账号或模型。
- 委派工具在 Team 成员中统一声明，Host 根据调用者、开关和目标 Project 校验。启动仅限该 Project 当前启用的 Agent owner；拥有 A Project 不授予 B Project 权限。普通 DSH Session 不获得 Team 工具或新行为。
- Worker 使用本机已安装的 CLI 和原生登录、设置。开启实验功能意味着允许使用配置的原生执行权限。Team 使用明确的启动配置支持真实文件修改；操作者可配置原生权限，模型不能在单次调用中改变它。Team 不另加工作目录沙箱或 checkout 写入锁，不替 owner 创建、合并或删除 worktree。owner 指定正确工作目录，并协调并行写入。没有显式目录时，使用发起时的当前工作目录。
- 委派不转移 Project 责任或 Task 的 accountable。Worker 代成员实施 Task 时，Claim 仍归该成员；Worker 不持有 Team 身份、私有记忆或协作工具，输出不能关闭、验收或改派 Task。现有独立验收规则保持不变。

## 3. 发起和结果去向

Codex 和 Claude Code 共用一个 Team Worker 工具，首版都交付发起（`start`）、同轮追加指令（`steer`）、停止（`stop`）和只读诊断（`inspect`）。Owner 发起时明确目标、必要背景、工作范围、完成标准和要交回的证据；Worker 不继承成员对话。发起工具在启动被接纳后返回 Team 执行编号，长任务在后台继续。启动失败要当场说明；已启动的执行不靠轮询。

| 发起时指定 | 归属和回传 |
| --- | --- |
| Task 或已有 Thread | Host 从目标确定 Project；结果、失败或停止事实记在原 Thread。发起者经正常的 Team Inbox 获知同一事实，Human 和有权访问的成员可在原 Thread 查。即使 Task 已关闭也保留执行事实，不代成员回复或重开。 |
| 仅 Project | 项目范围内的临时协助。结果只回发起的成员 Session；不创建 Thread／Task，也不发布到 Main。原 Session 不在时不补投。保留供发起者和 Human 按编号查看的最小私有诊断记录。 |
| 没有可确认的目标，或目标不一致 | 拒绝启动并说明应指定什么；不根据当前 UI、目录或成员拥有的任意 Project 猜测授权。 |

Host 在启动外部进程前记下执行编号、发起者与目标；同一发起请求重送不会启动两次。一次执行在发起时固定归属，终态只提交一次。Team 执行编号不等于 Harness activation 标识，也不等于原生会话 ID。Team 是任务归属、执行记录和 Inbox 的唯一权威；不把原生历史作为 Team 状态，也不重复发送 OAR 和 Team 的两份完成通知。外部输出是待核对的数据，不解释成指令或提及。

两种引擎共用终态和回传规则：正常完成回传已有回答；失败、超时和停止回传对应状态、可用的部分结果及安全诊断。引擎没有产生某类输出时，明确缺失，不拼造内容。Host 重启后无法确认的执行按下节处理。

## 4. 停止和运行中补指令

- 原发起成员和 Human 能停止一条正在启动或运行的执行。成员从同一工具按编号停止；Human 在“编辑 Agent”弹窗的正在运行 Worker 列表操作。这两个入口经 Host 控制同一个执行。开关关掉后不允许再派新 Worker，已有执行仍可停止。
- 请求停止后显示“停止中”，确认清理后才是“已停止”；清理失败明确显示无法确认停止。若执行先自然结束，保留实际结果。已有文件改动不回滚，不关闭或释放 Task。Host 重启失去句柄时，未确认终态的执行标为“结果未确认”，不重新接管、补跑或自动重试。正常卸载 Team 插件时先拒绝新启动，结束本插件持有的执行和清理，再关闭存储。
- Codex 与 Claude Code 的 steer 都是为同一次正在运行的执行追加文本。工具运行期间可以提交；验收观察当前工具返回后，同一轮的下一次模型调用收到指令。回执表示指令已提交，不表示模型已采用。已结束或停止中的执行拒绝追加；与结束竞争时若不能确认同轮送达，明确报告未确认，不报告同轮成功。不得转成排队、开启下一轮、重新派发或发送给另一执行。两种引擎都须通过正常路径和临近结束的验证，才能验收首版。

## 5. 失败诊断和只读查看

- 终态带引擎、Team 执行编号、失败阶段、可安全返回的原因和已有结果。原生会话建立后，保留原生 ID（Codex thread ID、Claude Code session ID）、原工作目录和原生存储位置；可获得时保留本次 Codex turn 的标识。建立会话前失败时说明没有原生记录。先保留诊断再释放活句柄，不以已收到模型文本代替清理确认。
- 发起成员和 Human 以 Team 执行编号按需只读检查对应执行，读取有限诊断和原生历史片段；不接受任意原生会话 ID、遍历其他任务或重新运行模型。缺失、尚未落盘、版本不支持或记录无法读取时，明确说明并保留已有的 Team 诊断。只有指向该次执行的已验证引用才可展示；不猜最新文件。不自动把原生记录、凭证或原始协议内容发进 Thread。
- 能读到诊断不意味着能续跑。首版不做全量 trace 浏览器、持续进度流、跨重启会话重连或自动重试。

## 6. 实现归属与验收

Team 自己实现一份 OAR provider 并使用 OAR 库的原生会话能力。复用 Harness 的注册、后台执行容量、取消和清理接口；Team 保存唯一的归属与通知，不修改 Harness 仓库或默认配置。借鉴 DSH 对启动清理、凭证环境和安全诊断的处理，验证 Team 实际发布版本的组合行为。

- **受控组合验证**：开关、目标 Project 权限、默认和显式引擎选择、两个执行反序结束不串结果、重复和陈旧请求、关闭 Task 后的记录、停止与正常结束竞争、清理失败、Host 重启的不确定终态。故障及关键竞争通过公开的 Team 控制入口施加。
- **原生 CLI 验收**：以发布组合分别验证 Codex 和 Claude Code 的正常、失败、超时和停止回传，以及进程退出后按 Team 编号只读获取正确的历史片段。分别观察两个引擎的追加指令进入同一轮下一步，并验证收尾时不会因此开启下一轮；不把接收回执当采用证明。两种引擎的共同动作均为首版验收项。
- **整体验收**：订阅发现异常，owner 判断后派 Worker 调查，并继续响应 Human；默认 Codex 与显式 Claude Code 各走一条委派去向。Human 能只停其中一次，另一次照常到达。再用轻量提醒检验 owner 可自行完成而不派活。浏览器检查按项目约定覆盖桌面和窄屏，并验证普通 DSH 不变。

引导沿用现有角色 prompt、工具说明和 Team domain skill：解释何时委派、如何给自包含说明、回到哪里处理结果；不新增专门的 Worker skill。交付后将已实现的权限、工具、配置与回传规则更新到对应维护文档和包 README。
