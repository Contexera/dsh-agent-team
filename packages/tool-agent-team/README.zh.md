# @contexera/dsh-agent-team/tools

[English](README.md) | 中文

面向 Agent Team Member 的模型工具。本包在调用方 Agent preset scope 内注册工具，不提供或替换 Host service。它不含 context 工具：Session 由引擎就地压缩，冷下来的一代由 Host 换代，两者都不是模型的决定。

## 工具

- `team_inbox` 列出调用方 Member 的有界未读 Thread 摘要，先按 direct work、再按最近活动排序；只有 Thread 存在真实 Task overlay 时才出现 Task standing。header 给出 unread/direct 总数与展示的 Threads 数（有界列表之外仍有未读时给出截断结论）；每个条目显示精确的 unread/direct 计数、Project ref 与 Task standing。页脚把阅读指向 `team_thread read`；渲染不携带 revision 与写令牌。
- `team_thread` 读取 Thread 或 Project 的 Main stream、分页历史，或按 ref 读回一条 Message。`threadRef` 是主身份；`taskRef` 只对 released task-only Client 是 Host alias。`beforeSequence`/`limit` 用于 history 分页，`read` 忽略它们，`message` 拒绝它们。三个 action 分开渲染：`read` 渲染结果、Thread 身份、导向（anchor 不是返回 fact 时给 bounded anchor subject）、Host 提供的背景（不是本次新确认的工作，当前上下文已完整可见时不重复）、只含 active Claims、已确认 Task reminders、带行内 unread/direct 标记的已确认 facts（正文已完整可见时渲染 `body already in current context; omitted`，仍计入确认）、当前 Task 卡（是状态，不是 Thread reading）、read-through/剩余未读页脚（只要这次 read 身后留有 Thread facts，页脚同时给出那些 facts 的数量）；`history` 渲染历史页（首页 full anchor、continuation 页 bounded subject，绝无当前 Claims 或上下文建议）；`message` 按 ref 逐字读回一条 Message。`read` 推进持久 watermark，是 next-write token 的读侧唯一来源——仅在未读清零时渲染；你自己的已提交 public mutation 也会回传一份新 token。没有可确认内容的 read——没有未读，或输出上限内没有选中任何 fact——什么都不推进、不写任何 operation，并渲染 `Read — no unread updates …` 或 `Read — no facts acknowledged …`，画面仍来自当前 projection。Activity facts 结构化渲染——actor、Task ref，以及每条 activity claim、完成、接受或 release 的 Claim refs。确认仍为 done 状态 Task 的未读验收的那次 read，把这些事实写进 facts，且不对读取者的上下文给出任何建议：模型没有 context 工具，也没有代际选择。Agent 的 `read` 与 `message` 输出整体有界：工具少选几条 fact，超长 Message 正文按有序字符分段返回，read 遇到未完整 Message 就停下，不越过它确认。唯一续读方式是重复同一个请求，地址（以及 `messageRef`）不变；Host 从当前 Session surface 的第一个缺失段继续，没有 offset 参数。Thread receipt 存储选中的界限，写入该字段之前的 receipt 仍按缺省 batch 解释。Main stream 的 read 补同样的近期 Message 背景，只确认被选中的前缀，并把 Thread 卡渲染在独立区，不因此把这些 Thread 标为已读。Human 的读取与 Remote 参数不变。
- `team_attention` 只回答你是否关注某个 Thread：`status` 只报告、不改变任何东西，`follow` 与 `unfollow` 改变 Attention。三者参数完全相同——Thread 地址与路由 Workspace——并渲染一行：Thread ref、可选 Task standing 与 following 状态。Attention 不是 reading：这里没有任何 action 渲染 Thread facts、确认未读或交写令牌，读一个 Thread 也从不改变你是否关注它。
- `team_message` 在 Project 的 Main stream 发言、创建顶层 Thread、回复既有 Thread。`start` 用 `kind: 'discussion'`（默认）或 `kind: 'task'` 原子创建 Task——已移除的 `asTask` 写法会被拒绝并指回 `kind`，绝不静默丢弃。Task start 另接受 `accountable`（Project owner 的 memberRef，或 `human`）与 `sourceThreadRefs`（派生自哪些讨论 Thread，卡片因此渲染在那里而非 Main stream）；两者在讨论 start 以及 `post`/`reply` 上都被拒绝而非丢弃，commit 的 start 回报实际记录的负责人。commit 的 start/reply 渲染一个 committed-verb 结果（Thread created / reply added），携带 Message、Thread 与可选 Task refs，以及恰好一个 next-write token hand-off。Reply 在检查令牌新鲜度前先拒绝未读工作。类型化拒绝以 `Not committed` 开头；完整且身份明确的 Message 事实可提供令牌供重新考虑，部分结果则指向 `read`。两者都不确认未读。
- `team_dm` 向同一 Workspace 内一个 enabled Agent Member 发送一条私有 direct message。它只接受 `memberRef` 与 `body`，别无其他——没有 Thread、没有 Task、没有写令牌、没有附件——多带的参数会被拒绝而不是被忽略。结果区分 `Delivered` 与 `Recorded, not delivered`（携带 delivery note 与禁止盲目重发的警告）；没有自动重投。Human 不能被 DM。
- `team_task` 通过 `board` 读取 Task board，通过 `list` 列出单个 Task 的 active Claims，通过 `claim`、`done`、`release` 修改调用方 Member 的 Direction Claim，通过 `accept`、`close`、`reopen`、`transfer` 了结或转交 Task，`promote` 则供 Project owner 把讨论 Thread 升格为 Task；它只适用于真实 Task。`board` 显示 open Task 与每个项目最近完成的 Task，每行给出 accountable owner，以及读者可验收时的待验收标记；`mine` 只留读者负责或正在执行的 Task。`list` 渲染 Task/Thread 身份与只有 active Claims 的 collision surface，且无写令牌。commit 的 mutation 点名动作（Claim created/completed/released、Thread promoted、Task accepted/closed/reopened/transferred），先渲染权威的受影响 Claim，再 hand-off 一个 next-write token。谁能 accept、close、reopen 或 transfer 由 Host 决定而非工具：工具只转发 action 与写令牌，`self_acceptance_forbidden` 或 `accountable_owner_required` 拒绝的出路来自 Host 的 recovery registry，并补上 Task 的当前状态与 accountable owner——那只有拒绝之后调用方自己才读得到。拒绝与 message 拒绝共享同一形式。Direction 互斥键执行 Unicode NFKC normalization、trim、空白压缩和确定性大小写折叠。
- `team_view` 是 address book：有界、按 membership 授权的 Project、顶层 Thread 与 Member 摘要——是当前的地址簿，不是工作队列。Threads 是唯一分页目录：newest-first 行携带 threadRef、Project ref、bounded anchor subject 与行内 Task standing（绝无第二个 Task 索引，也不渲染 revision 或消息数）。cursor 只延续 Thread 行；continuation 页只渲染 Threads，翻页可达全部获授权的顶层 Threads，包括 taskless 与不在首页的 taskful。

mention 在 Message 正文里撰写，形如 `@Handle`（`@` 必需、大小写不敏感；规则版本 2 下 `@all` 是普通文本，不通知任何人）；不存在收件人参数。mention 只把这条 Message 送达被点名的 Member 一次，不会使其开始关注。Closed Task 在 Human reopen 前拒绝 reply、Claim 和新的 Attention；taskless Thread 没有 Claim 或 Task resolution mutation path。

所有 agent-facing 渲染都在固定的 Team 协调时区 UTC+8 下携带带显式偏移的绝对事件时刻（`2026-09-08T17:00:00+08:00`）：`team_thread` 的 fact 行与 anchor 为每条 fact 标注其提交 operation 的时刻，`team_inbox` 行携带 `newestOccurredAt`，`team_view` 的 Thread 行携带 `lastActivityAt`，通知给出 `Occurred at:`，已提交变更从 receipt 渲染 `Committed at:`。同一存储时刻在任何重读路径中渲染完全一致；只渲染绝对 timestamp，绝不出现相对时间文案，且 sequence 与 revision——而非 wall-clock 时间——仍是顺序 authority。

Canonical result 以结构化字段暴露稳定 refs、可选 Task status、Thread revision、Claim history、Attention 和未读 facts。[Mutation fences](../../docs/team-collaboration/boundaries.zh.md#mutation-fences) 统一定义令牌来源、完整上下文凭据和拒绝恢复。浏览结果不提供令牌；完整的 `history`/`message` 事实可补上下文，但不确认未读。每次写入仍检查新事实、revision、权限和 Task 状态。工具执行通过准确的 live `exec.agent` 解析 actor；参数不能选择或冒充 actor，可选的 `workspace` 选择器只能在该 actor 已参与的 Workspace 中选择——接受完整 id 或至少 6 位十六进制的唯一前缀（与 branded refs 同一套容忍度），前缀匹配到多个候选时拒绝并列出全部候选。写操作的 request identity 由 sessionId 与 tool callId 派生。每个 Team tool 都把结果返回模型循环。

完整的已实现协议见 [`../../docs/team-collaboration/README.md`](../../docs/team-collaboration/README.md)。

## Composition

在 team-enabled Agent preset 内、`dsh-tools` 之后挂载本插件。插件只静态 inject `tools`；执行时从 live Agent context 读取 `agentTeam`，避免 Host 恢复 Member session 时形成依赖环。
