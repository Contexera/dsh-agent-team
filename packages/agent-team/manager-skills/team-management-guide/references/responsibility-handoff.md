# Establishing and handing over responsibility

The Human says: "I want someone to keep this repository's performance in good shape long-term."

## Judge and read

Ask what continuing result is meant, what the Human keeps (the latency budget, the acceptance call), and what is out of scope. Fixing one slow endpoint is a task; keeping performance in good shape is a continuing judgment. Then `team_overview` for existing Projects, Members, each owner's responsibility, who has no owner relation, and the Worker switch; when the repository matters, enter the checkout it reported and read its instructions.

## Propose the least structure

An existing owner whose domain covers the result gets the responsibility extended; create nothing. Otherwise decide the two halves separately: a Project that already carries the goal needs only a Member and an owner grant; a Member whose judgment fits needs only the Project; only when both are missing does the answer become one Member and one Project, whose description is the shared goal. Never one Agent per function (frontend, backend, test, docs), and never a Member invented for one acceptance. A one-off fix is a task for an existing owner or a Worker.

## Confirm, then write in dependency order

Creating a Member, granting ownership and archiving a Project expand trust: ask with `ask_user_question` once, showing the goal, the owner and the responsibility — not again for what the request already authorized. Then, in the branches you chose, `member_create` (confirm its activation), `project_create` (the shared goal as `description`, admitting only active Members), and `project_owner add` with the bounded responsibility, for example "owns runtime performance judgment: the latency budget, regression investigation and remediation priority".

## Hand off

A standard handoff is three facts: the Project's shared goal, the owner's responsibility, and a next context showing both plus the full owner list. The grant writes the public Activity, the Main stream marker and the ownership context, so no DM and no all-owner Thread is required; an offline Member sees the same facts when it resumes.

## Verify and report

The Human accepts at any time; an owner that did not implement or the Task's own accountable that never claimed it may accept only while the Task is in review. The owner records durable conclusions in its memory and the public record, and its next judgment uses them. Report who answers for what, which responsibility is `unspecified`, what is committed but not yet in effect, and what the Human must decide.
