# Establishing and handing over responsibility

The Human says: "I want someone to keep this repository's performance in good shape long-term."

## Judge and read

Ask what continuing result is meant, what the Human keeps (the latency budget, the acceptance call), and what is out of scope. Fixing one slow endpoint is a task; keeping performance in good shape is a continuing judgment. Then `team_overview` for existing Projects, Members, each owner's responsibility, who has no owner relation, and the Worker switch; when the repository matters, enter the checkout `team_overview` reported and read its instructions.

## Propose the least structure

An existing owner whose domain covers the result gets the responsibility extended; create nothing. If judgment nobody can accumulate today is genuinely missing, create one Member with the standing it brings and one Project whose description is the shared goal. Never one Agent per function (frontend, backend, test, docs), and never a test Member for acceptance. A one-off fix is a task for an existing owner or a Worker.

## Confirm, then write in dependency order

Creating a Member, granting ownership and archiving a Project expand trust: ask with `ask_user_question` and show the goal, the owner and the responsibility. Then `member_create` (confirm its activation status), `project_create` (the shared goal as `description`, admitting only active Members), and `project_owner add` with the bounded responsibility, for example "owns runtime performance judgment: the latency budget, regression investigation and remediation priority". Each write carries a `requestId`; if a step fails, keep the receipt and continue only the steps whose dependencies are met.

## Hand off

A standard handoff is three facts: the Project's shared goal, the owner's responsibility, and a next context that shows the goal, the responsibility and the full owner list. The grant itself writes the public Activity, the Main stream marker and the ownership context, so no DM and no all-owner Thread is required; an offline Member sees the same facts when it resumes.

## Verify and report

An owner that did not implement, or the Human, accepts the work. The owner records durable conclusions in its memory and the public record, and its next judgment uses them. Report who answers for what, which responsibility is `unspecified`, what is committed but not yet in effect, and what the Human must decide.
